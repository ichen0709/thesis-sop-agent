# 需求說明：研究生離校 SOP 問答 agent

> 狀態：第一版。沒有被決定的地方一律寫「待決定」。

## 1. 專案目標

企管系研究生從「考試申請、口試安排、辦理、成績送件、論文上傳」到「離校」，要走一長串流程。這個專案做一個網頁，學生在上面問問題，agent 只根據系辦提供的文件回答，並附上出處。文件裡查不到的，就請學生洽系辦。

這是期末專題，由我和 partner 一起做。

## 2. 使用者

- 主要使用者：企管系研究生。
- 其他使用者（助理、教授）：待決定。

## 3. 執行方式

- 網頁在我們自己的電腦上執行，瀏覽器開 `localhost`。
- 不上線、不需要 Discord、不需要 API 金鑰。
- 誰來操作、誰來展示：待決定。

## 4. 學生會問什麼

- 問題類型（流程順序、文件與表單、期限、窗口等）：待決定。
- 實際問題清單：待決定。

## 5. 回答要包含的內容

每則回答要有：

1. 出處：文件名稱加版本日期。
2. 下一步：學生接下來該做什麼。
3. 相關表單：要填的表單名稱。
4. 期限與窗口：截止日，以及負責的系辦人員或信箱。

文件裡沒寫的項目（例如文件沒有列窗口），就不編造，直接標示文件未載明。

回答裡的期限要標示該文件的適用學期或版本。同一件事有多個版本、或校級與系級規定不一致時怎麼處理：待決定。

## 6. 查不到文件依據時

明說「文件中沒有這項資訊」，並請學生洽系辦。不猜測，不用一般常識補答案。附不附系辦聯絡方式：待決定（要先拿到聯絡方式）。

## 7. agent 不能回答的事

- 文件沒寫或不確定的規定。
- 個案例外與特殊申請。
- 成績、審核結果的判斷。
- 與離校辦理無關的問題。

遇到這些一律請洽系辦，或說明不在服務範圍內。

## 8. 學生目前階段

網頁有階段選單，由學生手動選。選了之後，回答會針對該階段。

- 不儲存個人資料。重新整理頁面就重選。
- 階段要怎麼分（例如分幾段、名稱）：待決定。

## 9. 功能

### 確定要做

- 學生輸入問題，agent 只根據文件庫回答。
- 每則回答附出處（文件名加版本日期）、下一步、相關表單、期限與窗口。
- 查不到依據時，明說查不到並請洽系辦。
- 遇到不能回答的事（第 7 節），不回答並請洽系辦。
- 學生可手動選擇目前階段，回答依階段調整。
- 網頁區塊：
  - 流程圖（從申請到離校）。
  - 每一步要準備的文件清單。
  - 問答。
  - 三種辦理情境範例（是哪三種：待決定）。
- 防護（見第 12 節）。

### 預計之後做

待決定。

## 10. 文件庫

系辦提供的文件放在專案的文件資料夾。具體路徑與格式：待決定。

每份文件要登記三項資料：

| 欄位 | 說明 |
|---|---|
| 來源 | 誰提供、從哪裡取得（例如系辦、系網頁） |
| 版本日期 | 這份文件的版本日期，同時寫在檔頭 |
| 可否公開 | 可以公開，或不可公開 |

做法：

- 系辦給新版時，手動替換檔案，並在檔頭記版本日期，同步更新登記資料。
- 舊版另外封存，不給 agent 讀取。
- 不可公開的文件不放進 git repo（repo 已設定忽略原始文件與 env）。這類文件怎麼處理：待決定。
- 文件的原始格式（PDF、Word 等）與如何轉成 agent 可讀的文字：待決定。
- 文件由誰負責向系辦收集與確認：待決定。

## 11. 技術選擇

這些由我和 Claude 決定，不需要使用者操作。

- 語言與環境：Python 3.12，用 uv 管理。
- agent：呼叫 `claude -p`（Claude Code 的非互動模式），使用已登入的 Claude Code，不需要另外申請 API 金鑰。
- 網頁：輕量的本機網頁伺服器（Python），瀏覽器打開 localhost 使用。
- 流程圖與清單：用網頁本身（HTML/CSS）畫，不依賴外部網路資源，離線也能顯示。
- 理由：整個專案在自己的電腦上跑，不需要部署與帳號系統，工具越少越好維護。

## 12. 防護

- 暫存資料夾：`claude -p` 在隔離的暫存資料夾裡執行，只能看到文件庫的內容。
- 權限限制：`claude -p` 只開放讀取文件所需的最小權限，不允許執行指令、不允許寫入。
- 問題當資料：學生輸入的內容只當成要回答的問題，不當成指令。
- 輸出檢查：回答顯示前檢查有沒有出處；沒有出處的回答改為「請洽系辦」。
- 輸出檢查（出處核對）：回答引用的文件名稱與版本日期，必須對得上文件庫登記的文件；對不上的視為沒有出處，改為請洽系辦。是否進一步核對引用的段落真的存在於該文件：待決定。
- 網頁文字清洗：回答與輸入顯示在網頁前先跳脫處理，避免網頁被插入程式碼。

各項防護的具體做法與測試方式：待決定（開發時再寫）。

## 13. 開發順序

每一步都要能單獨測試。

1. 防護：暫存資料夾、`claude -p` 權限限制、問題當資料、輸出檢查、網頁文字清洗。
2. 文件庫。
3. 問答。
4. 流程圖與文件清單。
5. 情境範例。
6. 請承辦人用三種辦理情境檢核。

承辦人是誰、怎麼聯絡：待決定。

## 14. 驗收

由承辦人用三種辦理情境檢核。判斷標準：

- 答案正確。
- 附出處，且出處對得上文件庫。
- 不編造。
- 不確定時請洽系辦。

三種辦理情境是哪三種、承辦人怎麼檢核、檢核結果怎麼記：待決定。

- 展示方式與操作者。
- 引用的段落是否要核對真的存在於該文件。
- 期限標示適用學期或版本後，同一件事有多個版本、或校級與系級規定不一致時怎麼處理。
